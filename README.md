# PERN приложение: ПОДПИСНЫЕ ИЗДАНИЯ

Система управления подписками на издания (газеты и журналы) для отделения Белпочты.

## Установка и настройка

1. **Клонируйте репозиторий и установите зависимости:**

```bash
npm install
```

2. **Создайте файл `.env` в корне проекта:**

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=subscription_publications
DB_USER=postgres
DB_PASSWORD=your_password
PORT=5000
```

3. **Создайте базу данных:**

```bash
npm run db:create
```

Или создайте базу данных вручную в PostgreSQL:

```sql
CREATE DATABASE subscription_publications;
```

4. **Заполните базу данных тестовыми данными (опционально):**

```bash
npm run db:seed
```

Это создаст 55 записей:
- 18 изданий (газеты и журналы)
- 17 получателей
- 20 подписок

Или выполните SQL скрипт вручную:

```bash
psql -U postgres -d subscription_publications -f server/scripts/seed.sql
```

5. **Запустите сервер:**

```bash
# Режим разработки (с автоперезагрузкой)
npm run dev

# Или в обычном режиме
npm start
```

Сервер будет доступен по адресу: `http://localhost:5000`

5. **Установите зависимости клиентской части и запустите клиент:**

```bash
cd client
npm install
npm run dev
```

Клиент будет доступен по адресу: `http://localhost:3000`

## Структура базы данных

### Таблица `publications` (Издания)
- `id` - первичный ключ
- `index` - индекс издания (уникальный)
- `type` - вид издания (газета/журнал)
- `title` - название издания
- `monthlyPrice` - стоимость подписки на 1 месяц (руб.)
- `image` - изображение издания (base64, опционально)

### Таблица `recipients` (Получатели)
- `id` - первичный ключ
- `code` - код получателя (уникальный)
- `fullName` - ФИО получателя
- `street` - улица
- `house` - дом
- `apartment` - квартира (опционально)
- `image` - изображение получателя (base64, опционально)

### Таблица `subscriptions` (Подписки)
- `id` - первичный ключ
- `recipientId` - внешний ключ на получателя
- `publicationId` - внешний ключ на издание
- `duration` - срок подписки (1, 3 или 6 месяцев)
- `startMonth` - месяц начала доставки (1-12)
- `startYear` - год начала доставки
- `image` - изображение подписки (base64, опционально)

## REST API

### Базовый URL: `http://localhost:5000/api`

### Издания (`/api/publications`)

#### Получить все издания
```
GET /api/publications
```

**Параметры запроса:**
- `page` - номер страницы (по умолчанию: 1)
- `limit` - количество записей на странице (по умолчанию: 10)
- `sortBy` - поле для сортировки (по умолчанию: id)
- `sortOrder` - порядок сортировки: ASC или DESC (по умолчанию: ASC)
- `search` - поиск по индексу и названию
- `type` - фильтр по виду издания (газета/журнал)
- `minPrice` - минимальная цена
- `maxPrice` - максимальная цена

**Примеры:**
```
GET /api/publications?page=1&limit=5
GET /api/publications?sortBy=title&sortOrder=ASC
GET /api/publications?search=газета&type=газета
GET /api/publications?minPrice=10&maxPrice=50
```

#### Получить издание по ID
```
GET /api/publications/:id
```

#### Создать издание
```
POST /api/publications
Content-Type: application/json

{
  "index": "12345",
  "type": "газета",
  "title": "Название газеты",
  "monthlyPrice": 15.50
}
```

#### Обновить издание
```
PUT /api/publications/:id
Content-Type: application/json

{
  "title": "Новое название",
  "monthlyPrice": 20.00
}
```

#### Удалить издание
```
DELETE /api/publications/:id
```

#### Проверить существование издания
```
GET /api/publications/check/:id/exists
```

## Валидация данных

Все модели имеют встроенную валидацию:

- **Издания:**
  - Индекс: обязательное, уникальное, 1-20 символов
  - Вид: только "газета" или "журнал"
  - Название: обязательное, 1-200 символов
  - Цена: обязательное, неотрицательное число

- **Получатели:**
  - Код: обязательное, уникальное, 1-20 символов
  - ФИО: обязательное, 1-200 символов
  - Улица: обязательное, 1-100 символов
  - Дом: обязательное, 1-20 символов
  - Квартира: опциональное, до 20 символов

- **Подписки:**
  - Срок: только 1, 3 или 6 месяцев
  - Месяц начала: от 1 до 12
  - Год начала: от 2000 до 2100

**7.5. Создание подписки с несуществующим изданием**
- **Метод:** POST
- **URL:** `http://localhost:5000/api/subscriptions`
- **Body:**
```json
{
  "recipientId": 1,
  "publicationId": 99999,
  "duration": 6,
  "startMonth": 1,
  "startYear": 2024
}
```
- **Ожидаемый результат:** Статус 404, сообщение "Издание не найдено"

**7.6. Создание издания с дублирующимся индексом**
- **Метод:** POST
- **URL:** `http://localhost:5000/api/publications`
- **Body:**
```json
{
  "index": "10001",
  "type": "газета",
  "title": "Дубликат",
  "monthlyPrice": 10
}
```
- **Ожидаемый результат:** Статус 400, сообщение об уникальности индекса

#### Сценарий 8: Комплексное тестирование

**8.1. Полный цикл работы с изданиями**
1. Создать издание → сохранить ID
2. Получить издание по ID → проверить данные
3. Обновить издание → проверить изменения
4. Проверить существование → должно быть true
5. Удалить издание
6. Проверить существование → должно быть false
7. Попытка получить удаленное издание → 404

**8.2. Тестирование связей между сущностями**
1. Создать получателя → сохранить ID
2. Создать издание → сохранить ID
3. Создать подписку для этого получателя и издания
4. Получить получателя по ID → проверить наличие подписки
5. Получить издание по ID → проверить наличие подписки
6. Попытка удалить получателя → должна быть ошибка (есть подписки)
7. Удалить подписку
8. Удалить получателя → должно быть успешно

**8.3. Тестирование пагинации**
1. Получить первую страницу (page=1, limit=5)
2. Проверить общее количество записей
3. Вычислить количество страниц
4. Получить последнюю страницу
5. Попытка получить страницу за пределами диапазона → должна вернуть пустой результат

1. **Адаптивный интерфейс:**
   - Полностью адаптивный дизайн для всех устройств
   - Современный и удобный UI

2. **State Management (Redux):**
   - Redux Toolkit для управления состоянием
   - Отдельные slices для каждой сущности
   - Асинхронные действия через createAsyncThunk

3. **Роутинг:**
   - React Router для навигации между страницами

   - Валидация форм на стороне клиента

6. **Удаление с подтверждением:**

9. **Пагинация, сортировка, фильтрация:**
   - Пагинация списков
   - Сортировка по любому полю
   - Фильтрация по нескольким полям
   - Поиск по нескольким полям одновременно

## Особенности реализации

1. **Связи между таблицами:**
   - Получатель может иметь несколько подписок
   - Издание может иметь несколько подписок
   - Каждая подписка принадлежит одному получателю и одному изданию

2. **Ограничения:**
   - Нельзя удалить получателя, у которого есть подписки
   - При создании/обновлении подписки проверяется существование получателя и издания

3. **Серверная функциональность:**
   - Полная поддержка CRUD операций
   - Пагинация для всех списков
   - Сортировка по любому полю
   - Фильтрация по нескольким полям одновременно
   - Поиск по нескольким полям одновременно
   - Обработка ошибок и валидация

4. **Клиентская функциональность:**
   - Адаптивный интерфейс
   - Redux для управления состоянием
   - Роутинг между страницами
   - Формы с валидацией
   - Подтверждение удаления
   - Детальный просмотр с фото
   - Загрузка и отображение изображений
