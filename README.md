# MERN приложение - Подписные издания

Полнофункциональное MERN приложение для управления подписными изданиями Белпочты.

## Описание проекта

Система предназначена для учета получателей и выписанных ими изданий. База данных состоит из трех коллекций:
- **Издания** (Publications) - газеты и журналы, на которые можно оформить подписку
- **Получатели** (Recipients) - граждане, оформляющие подписку
- **Подписки** (Subscriptions) - информация об оформленных подписках

## Установка и запуск

### Требования

- Node.js (версия 14 или выше)
- MongoDB (локально или MongoDB Atlas)

### Установка зависимостей

```bash
npm install
```

### Настройка переменных окружения

Создайте файл `.env` в корне проекта со следующим содержимым:

```
MONGODB_URI=mongodb://localhost:27017/subscriptions_db
PORT=5000
```

Для MongoDB Atlas используйте:
```
MONGODB_URI=mongodb+srv://username:password@cluster.mongodb.net/subscriptions_db
```

### Заполнение базы данных исходными данными

Перед запуском сервера рекомендуется заполнить базу данных тестовыми данными из JSON-файлов:

```bash
# Заполнение базы данных (без удаления существующих данных)
npm run seed

# Заполнение базы данных с очисткой существующих данных
npm run seed:clear
```

Скрипт загрузит данные из файлов:
- `data/publications.json` - 15 изданий
- `data/recipients.json` - 20 получателей
- `data/subscriptions.json` - 32 подписки

**Всего будет создано не менее 50 записей** (67 записей в совокупности).

### Запуск сервера

```bash
# Обычный режим
npm start

# Режим разработки с автоперезагрузкой
npm run dev
```

Сервер будет доступен по адресу `http://localhost:5000`

### Запуск клиентской части

```bash
# Перейдите в папку client
cd client

# Установите зависимости
npm install

# Запустите приложение
npm run dev
```

Клиентское приложение будет доступно по адресу `http://localhost:3000`

**Важно:** Убедитесь, что сервер запущен перед запуском клиентской части.

## API Endpoints

### Издания (Publications)

- `POST /api/publications` - Создание нового издания
- `GET /api/publications` - Получение списка изданий (с пагинацией, сортировкой, фильтрацией, поиском)
- `GET /api/publications/:id` - Получение издания по ID
- `GET /api/publications/:id/exists` - Проверка существования издания
- `PUT /api/publications/:id` - Обновление издания
- `DELETE /api/publications/:id` - Удаление издания

**Параметры запроса для GET /api/publications:**
- `page` - номер страницы (по умолчанию: 1)
- `limit` - количество записей на странице (по умолчанию: 10)
- `sort` - поле для сортировки (по умолчанию: createdAt)
- `order` - порядок сортировки: asc или desc (по умолчанию: desc)
- `search` - поиск по индексу, названию и типу издания
- `type` - фильтр по типу издания (газета/журнал)
- `minPrice` - минимальная цена подписки
- `maxPrice` - максимальная цена подписки

**Пример запроса:**
```
GET /api/publications?page=1&limit=10&sort=monthlyPrice&order=asc&type=журнал&minPrice=10&maxPrice=50
```

### Получатели (Recipients)

- `POST /api/recipients` - Создание нового получателя
- `GET /api/recipients` - Получение списка получателей (с пагинацией, сортировкой, фильтрацией, поиском)
- `GET /api/recipients/:id` - Получение получателя по ID
- `GET /api/recipients/:id/exists` - Проверка существования получателя
- `PUT /api/recipients/:id` - Обновление получателя
- `DELETE /api/recipients/:id` - Удаление получателя

**Параметры запроса для GET /api/recipients:**
- `page`, `limit`, `sort`, `order` - аналогично изданиям
- `search` - поиск по коду, ФИО, адресу
- `code` - фильтр по коду получателя
- `street` - фильтр по улице

**Пример запроса:**
```
GET /api/recipients?page=1&limit=20&sort=fullName&order=asc&search=Иванов
```

### Подписки (Subscriptions)

- `POST /api/subscriptions` - Создание новой подписки
- `GET /api/subscriptions` - Получение списка подписок (с пагинацией, сортировкой, фильтрацией, поиском)
- `GET /api/subscriptions/:id` - Получение подписки по ID
- `GET /api/subscriptions/:id/exists` - Проверка существования подписки
- `PUT /api/subscriptions/:id` - Обновление подписки
- `DELETE /api/subscriptions/:id` - Удаление подписки

**Параметры запроса для GET /api/subscriptions:**
- `page`, `limit`, `sort`, `order` - аналогично изданиям
- `search` - поиск по коду получателя, ФИО получателя, индексу издания, названию издания
- `recipientCode` - фильтр по коду получателя
- `publicationIndex` - фильтр по индексу издания
- `duration` - фильтр по сроку подписки (1, 3 или 6 месяцев)
- `startMonth` - фильтр по месяцу начала доставки (1-12)
- `startYear` - фильтр по году начала доставки
- `minYear`, `maxYear` - фильтр по диапазону годов

**Пример запроса:**
```
GET /api/subscriptions?page=1&limit=10&recipientCode=REC001&startYear=2024
```

## Валидация данных

Все модели используют встроенные и пользовательские валидаторы Mongoose:

- **Издания**: проверка формата индекса, типа издания, длины названия, положительности цены
- **Получатели**: проверка формата кода, структуры ФИО, формата адреса
- **Подписки**: проверка существования получателя и издания, валидности срока подписки, месяца и года

## Тестирование API

Для тестирования всех эндпоинтов рекомендуется использовать Postman:

1. Импортируйте коллекцию запросов (можно создать вручную на основе документации выше)
2. Убедитесь, что сервер запущен
3. Проверьте все CRUD операции для каждой коллекции
4. Протестируйте пагинацию, сортировку, фильтрацию и поиск

## Особенности реализации

### Серверная часть

1. **Пагинация**: Все списки поддерживают пагинацию через параметры `page` и `limit`
2. **Сортировка**: Сортировка по любому полю модели через параметры `sort` и `order`
3. **Фильтрация**: Фильтрация по нескольким полям одновременно
4. **Поиск**: Поиск по нескольким полям одновременно с использованием регулярных выражений
5. **Обработка ошибок**: Централизованная обработка ошибок с понятными сообщениями
6. **Валидация**: Валидация на уровне моделей с пользовательскими валидаторами
7. **Проверка существования**: Отдельные эндпоинты для проверки существования записей

### Клиентская часть

1. **Адаптивный интерфейс**: Полностью адаптивный дизайн для всех устройств
2. **State Management**: Redux Toolkit для управления состоянием приложения
3. **Роутинг**: React Router для навигации между страницами
4. **Формы**: Полнофункциональные формы для создания и редактирования записей
5. **Валидация форм**: Клиентская валидация с отображением ошибок
6. **Подтверждение удаления**: Модальные окна подтверждения перед удалением
7. **Детальный просмотр**: Модальные окна с подробной информацией и изображениями
8. **Уведомления**: Toast-уведомления для успешных операций и ошибок
9. **Фильтрация и поиск**: Интерактивные фильтры и поиск на каждой странице
10. **Пагинация**: Навигация по страницам с отображением общего количества записей
11. **Сортировка**: Кликабельные заголовки таблиц для сортировки данных
12. **HTTP-запросы**: Axios для всех API-запросов с централизованной обработкой ошибок
